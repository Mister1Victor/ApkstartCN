# Internationalization (i18n)

ApkStart's UI is localized with a small zero-dependency JSON system.

## Supported locales

| Locale  | File                            | Notes                                  |
| ------- | ------------------------------- | -------------------------------------- |
| `en`    | `src/i18n/locales/en.json`      | English. Fallback for missing keys.    |
| `zh-CN` | `src/i18n/locales/zh-CN.json`   | Simplified Chinese (original strings). |

## How the locale is chosen

The preference lives in `settings.language`:

- `auto` (default) — follow the Windows display language
  (`zh*` → `zh-CN`, anything else → `en`)
- `en` / `zh-CN` — forced

Users can change it in **Settings → Interface → Language**; it applies
immediately (renderer re-renders, the tray menu is rebuilt) without a restart.

## Using it in code

Main process / Node (`src/main.js`, core modules):

```js
const { t } = require('../i18n');
tray.setToolTip(t('main.tray.tooltip'));
notify(t('main.notify.installDone'), t('main.notify.installDoneBody', { name }));
```

Renderer (`src/ui/*.js`): the main process hands the dictionary over via
`window.apkstart.getI18n()`; `src/ui/i18n.js` exposes the same `t()`:

```js
const t = (k, p) => window.I18n.t(k, p);
toast({ title: t('app.install.done', { name }) });
```

Static HTML should not hard-code text; annotate instead:

```html
<button data-i18n="ui.installApk">Install APK</button>
<input data-i18n-placeholder="ui.searchPlaceholder" />
<span data-i18n-html="empty.desc"></span>   <!-- only if the string has markup -->
<button data-i18n-title="common.settings"></button>
<img data-i18n-alt="settings.aboutQrAlt" />
```

## Rules for strings

- Keys are flat, dot-namespaced (`settings.*`, `app.*`, `main.tray.*`, …).
- Interpolation is `{name}` placeholders; names must match across locales
  and at the call site.
- Every key must exist in **both** locale files. A missing key falls back
  to English, then to the key itself — visible in review, so keep them in sync.
- Do not localize: log lines, comments, commands, file paths, or strings
  used for control-flow matching.

## Adding a language

1. Copy `en.json` to `src/i18n/locales/<locale>.json` and translate the values.
2. Register it in `src/i18n/index.js` (`MESSAGES`) and in
   `normalizeLocale()` if it needs alias mapping (e.g. `zh-TW` → a new file).
3. Add an `<option>` for it in the language `<select id="setLanguage">`
   in `src/ui/index.html`.

## Scope of this change

Localized: the main window (`index.html` / `app.js`), the app-window shell
(`shell.html` / `shell.js`), and the main process (`main.js`: tray, dialogs,
notifications, toasts, update flow, self-check summaries).

Not yet localized (follow-up): strings generated inside `src/core/`
(doctor report details, installer/provision progress messages, emulator and
updater internals) that are passed to the UI as opaque message payloads.
The infrastructure already covers them — core modules can
`require('../i18n')` and call `t()` the same way.
